# UI・測定値の表・励まし履歴（PR #8更新）

既存PR #8のホーム・設定を引き継いで更新する。baseは実機確認済みの通知・回答詳細を含むPR #7のブランチのまま。PR #9はこのUI・履歴版を取り込んで朝夜の予約を別レビューにする。いずれもマージしない。認証・既存回答・Keystore鍵・設定を削除しない。

## 目標入力と設定

目標体重はDecimalキーボードで入力し、kgは入力欄の外に置く。貼り付けも保存時にBigDecimalとして検証し、正の有限数値だけを正規化して保存する。空・0・負・NaN・Infinity・単位付きは拒否。入力長と桁の安全上限を設け、巨大な貼り付けでメモリを消費しない。小数2桁固定の制限を外した。

期限は任意。Androidのカレンダーで選択・変更し、解除できる。目標と期限は「保存する」で確定する。期限切れでも、ホームの専用導線から手動生成を続けられる。通常の自動励ましは再設定待ちで停止する方針で、実際の無操作AI生成は未対応。

モデル・人格・共通補足・接続・Health Connectは既存設定を維持。モデル利用不可を生成時に発見した場合も再選択へ案内する。人格を変えても旧回答の当時名は変えない。旧回答に名前がなければ補わない。

通知設定は朝・夜の2枠。両方有効なら朝より夜が後であることをUIと保存処理で検証する。旧1枠設定は同じ時刻・有効状態で朝枠へ移し、夜は初期無効。時刻から朝／夜を推測して変更しない。このUI版単独は設定保存のみで、予約配信も自動生成も無効と明記する。

## 測定値の表とスナップショット

手動取得画面、送信前確認、回答詳細は項目／値・単位／測定日時・集計期間の表を使う。項目別・日付順に表示し、縦画面の折り返しを使って横スクロールを避ける。提供元は補足行に表示。記録なし・未許可・取得失敗と、実際の0歩を区別する。

新しい回答schema3は生成時の表データと朝／夜／手動区分を保存する。使用データ文字列も暗号化した原本として保持するが、画面に長文やJSONのまま並べない。旧schema1/2は既知の書式を読み取り専用で表に変換し、数値や欠損理由を推測しない。未知の旧書式は変換できない旨の行を表示し、原本を勝手に書き換えない。全文は詳細の上側、使用値の表はその下。通知タップは現在値や最新回答へ置換せず、IDで該当回答を開く。

## 朝・夜・手動の入力

Health Connect設定に「朝の入力を確認」「夜の入力を確認」を用意する。これは送信しない比較画面で、追加AI送信・回答保存・通知はない。

朝の取得終端は端末現地日付の当日0時で、当日の体重・体脂肪率・歩数を除外する。体重等は終端まで30日、歩数は前日までの7日の日別集計。夜・手動は生成時点までの当日を含む従来の30日／7日で、当日を中心に振り返る。朝に手動ボタンを押してもMANUALの振り返りであり、時刻で朝モードへ変えない。古い値は測定日時を保持し、当日の実績にしない。欠損理由・実績を推測せず、全未取得でも目標・人格・補足で生成できる。過去の回答は送らない。

将来の朝生成はその日の行動を一つ提案し、夜は振り返る方針とする。現段階では無操作AI生成を接続しないため、朝／夜のAI生成成功を主張しない。予約検証も元回答の生成日時・区分を書き換えない。

## 履歴

ホームから一覧へ入り、新しい順に生成日時、朝／夜／手動、生成当時の人格名、安全な短文を表示する。20件単位のkeysetページングで、タップは通知と同じ詳細を開く。旧回答はこれまで全て手動生成だったためMANUALとして読む。朝夜の区分は将来の生成記録にも使える保存形式である。

健康値・全文・人格名・短文は既存の暗号化ファイルを保持する。IDと生成時刻だけをnoBackupFilesDir内のSQLite索引に置く。初回だけ既存ファイルを索引化し、以降は1ページ分の回答だけを復号する。索引もバックアップから除外される。

個別削除、一括削除の確認ダイアログに対応する。一括は未読込ページも含む。回答と使用データのファイルを削除し、別保存先の目標・人格・連携設定・鍵には触れない。削除済みIDを記録し、残っている通知から開いた場合は「削除済み」と案内して別回答に切り替えない。削除中に終了しても削除済みIDが復活しないよう、削除記録を先に確定する。ファイル削除が失敗した場合はエラーを表示し再実行できる。物理消去の成功や端末全体からの復元不能を過剰に保証しない。

## Androidだけの試験

1. 最新のUI・履歴APKを既存の診断版へ上書きする。アンインストールやデータ消去・鍵再生成をしない。
2. 設定→目標で小数キーボードと外側kgを確認。68.875等の小数を入力・貼り付けして保存し、0・負・文字・単位付きが保存されないことを確認する。カレンダーで期限を選択・変更し、解除して保存できること、再起動後の保持を確認する。
3. 既存のモデル・人格の選択と編集保持を確認する。カスタムの追加・編集・削除、使用中カスタム削除後のトレーナーへの復帰、初期人格の個別リセットと共通補足を確認する。
4. Health Connectの取得画面で項目別の表と日時を確認する。当日データがある状態で朝／夜の送信しないプレビューを比較し、朝には当日分がなく夜には含まれることを確認する。記録なしと未許可、0歩を区別する。
5. 手動生成の送信前の表を取得値と照合し、確認して送信する。朝に押しても振り返り用であること、通常生成で通知しないことを確認する。
6. 詳細の上に全文、下に生成時の表が出ることを確認する。その後測定・目標・人格を変えても旧詳細が変わらないこと、ホーム・履歴・詳細の当時名を確認する。
7. 履歴を新しい順に開き、通知からも同じIDの詳細になることを確認する。件数が多ければ「続きを読み込む」で追加されることを確認する。個別削除後に該当通知をタップし、削除済みの案内を確認する。
8. 一括削除でキャンセルは保持、確認後は未読込分も消えること、目標・人格・認証設定は残ることを確認する。必要な履歴まで消さないよう、削除対象はユーザーが判断する。
9. 朝だけ／夜だけ／両方の設定保存と時刻の順序エラーを確認する。このUI APKは配信しない。予約到着は別の予約版で試す。

## 測定日時と表示上の行まとめ

取得・送信前確認・回答詳細の測定日時／期間は、閲覧時の端末現地時刻で `yyyy/MM/dd HH:mm` とする。秒・ミリ秒・タイムゾーンは表示しない。体重と体脂肪率はそれぞれ、現地日付と丸める前の測定値が等しい記録だけ表示上まとめ、最新の測定時刻を代表にする。提供元は併記する。日付や元の値が異なる記録と歩数はまとめない。送信前確認で実際にまとめた場合は「同じ値の記録を表示上まとめています」と表示する。

元の記録・保存データ・目標到達判定・ChatGPT送信内容は変更しない。旧回答の既知形式にも表示時だけ適用する。時刻を解釈できない旧記録は「日時不明」とし、推測しない。

Android試験：同日に同じ値を複数回測定し、3画面で最新の時刻の1行になること、注記が送信前に出ることを確認する。異なる値・別の日・異なる項目は別行になること、全日時が端末現地時刻の分までであることを確認する。今回の表示変更は実機未確認。

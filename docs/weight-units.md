# 体重の単位（kg / lb）

設定→体重の単位で選択します。表示言語とは独立して暗号化設定へ保存し、新規・旧設定とも初期値はkgです。Health Connectの読み取り値、目標体重、回答の測定値スナップショットはkgのまま保存します。目標到達判定も従来のkg値です。旧設定schema 1/2、旧回答schema 1/2/3を維持します。

1 lb = 0.45359237 kg（正確な定義）をBigDecimalで換算します。通常の表示は小数2桁まで四捨五入（HALF_UP）、末尾のゼロを省略します。入力欄は小数6桁まで表示し、入力も小数6桁以内の正の通常の十進数を受け付けます。指数・単位付き・カンマ・非数・負値は拒否します。全角数字はNFKC正規化します。lb入力は定義値との乗算結果をkgとして丸めず保存します。既存の高精度目標も保持します。単位変更だけでは目標を再保存せず、目標欄を編集しない保存（日付だけの変更を含む）では元のkg文字列を保持します。

ホーム・手動取得表・送信前確認・回答詳細の数値表は選択単位を使います。表示のまとめは元の値を比較してから換算するため、表示上同じ値でも元値が異なる記録は別行です。体脂肪率・歩数は変えません。未取得や未許可をゼロにしません。

朝・夜・手動は共通のprepareGenerationで開始時点の設定を固定します。送信する目標と各体重は選択単位に統一し、回答本文の単位を指示します。kgは元の精度、kg→lbは小数12桁まで四捨五入した換算値を送ります。送信確認の概要は2桁表示、「送信データをすべて見る」には実際の送信換算値を表示します。確認後に設定を変更してもその確認内容の単位を使います。保存済み短文・全文・送信内容は書き換えず、詳細の測定表だけ現在の選択単位へ換算します。短文の数値検出／固定文への置換は従来どおりです。

## Androidだけの試験

1. GitHub Actionsの本PRの成功した実行からhagemashi-debug-apk（通常版）またはhagemashi-diagnostic-apk（診断版）を取得し、ZIPを展開してAPKを更新インストールします。既存アプリを削除しないでください。署名エラー時は削除せず報告してください。
2. 旧設定の目標・人格・モデル・連携・履歴を確認します。初期単位がkgであること、新規インストールもkgであることを確認します。
3. kgで68.123456を保存し、lbへ切り替えます。ホーム／取得表／目標欄を確認し、日付だけ変更して保存します。kg↔lbを繰り返し、アプリ終了・再起動後にkgの目標欄が68.123456のままであることを確認します。
4. lbで150を保存し、kgで68.038856（入力欄は6桁表示）となることを確認します。編集せず保存後にlbへ戻って150であることを確認します。入力0、負数、文字、貼り付けの単位付き文字、小数7桁を保存できないことを確認します。
5. Health Connect取得表の体重が切り替わり、日時・件数・体脂肪率・歩数・欠損状態が変わらないことを確認します。
6. 各単位で手動生成の概要と全データを開き、目標と体重の単位が一致することを確認して生成します。本文の単位と、通常の手動生成で通知が出ないことを確認します。
7. 過去の回答を履歴と通知から開き、本文・短文・タイトルが変わらず、測定表だけ選択単位になることを確認します。
8. 朝／夜予約の自動生成を各単位で試し、朝は前日まで・夜は当日を含む記録、本文の単位、通知に測定値がないこと、通知から該当する詳細が開くことを確認します。

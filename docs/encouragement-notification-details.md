# 生成済みの励ましの検証通知と回答詳細

## 基点と実機確認の境界

PR #5（読み取り）・#6（実データ手動生成）は未マージ。#6の最新先端 `1ae78813c7f6f590b9a125aad7d73f816b8a20c5` を確認し、ここから `feat/encouragement-notification-details` を作成した。今回のPRのbaseは `feat/health-manual-generation`。これにより通知・詳細・保存の固有差分をレビューできる。親PRがmainへ入った後は順にbaseをmainへ切り替え、差分と最新CIを確認する。今回、いずれのPRもマージしない。

ユーザーから、Health Connectの実データを使った手動生成と回答本文表示がAndroid実機で成功したとの報告を受領し、#6に記録した。成功時のAPK識別子や型ごとの詳細は未指定なので推測しない。今回のJSON形式の生成、短文判定、保存、通知権限、通知タップと詳細の実機動作は未確認である。

認証はブラウザのタブを閉じて戻る方式を維持する。Keystoreによる認証情報の保存、SIWCの通信処理、モデル一覧、ストリーム完了判定、Health Connectの読み取り期間・権限・送信前確認は変更しない。SDK・依存・CI署名鍵も維持する。

## 生成結果と短文の安全性

送信前に表示する生成方針を更新し、既定人格にshort（通知用40〜60文字目安）とfull（全文200〜300文字目安）のJSONオブジェクトを要求する。SIWCのリクエストに新しいパラメータは追加せず、既存のinstructions/inputだけを使う。過去の回答は送らず、store=falseとストリーム完了・非空回答の検証を維持する。

JSONに有効なfullがあれば全文を省略せず保持する。shortがない／文字列でない／40〜60文字に収まらない場合は固定文にする。数字、全角・アラビア数字、ローマ数字・囲み数字などのUnicode数値、漢数字、単位・健康ラベル、Latin文字、不可視制御文字や記号なども保守的に検査する。正規化後にも判定し、怪しい短文は全文から切り出さず、数値のない固定文へ差し替える。過剰な判定により安全な表現も固定文になることがある。通知構築時にも再検査する。

固定文：

> 今日も自分のペースを大切に。できたことを認めながら、無理なく続けるあなたを応援しています。

旧形式のプレーンテキストが返った場合も、全文として残し通知短文は固定文にする。壊れたJSONや空のfullは安全なPROTOCOLエラーとし、生の応答・例外メッセージは診断に表示しない。全文の文字数は目安で、途中で切り捨てない。旧固定ダミーデータ生成の技術診断は従来どおりで、この保存・通知対象は実データ手動生成（全項目未取得の場合を含む）である。

## 保存と詳細

完了した回答ごとに新しいUUIDを生成し、short、full、生成日時、生成に実際に使用した入力文字列（目標、値、測定日時、集計期間、提供元、欠損理由）、健康値の有無を保存する。入力の再取得や生成時の最新値への置換はしない。健康値の有無は取得結果から決め、目標体重や期間の日付があるだけで健康値取得済みとは扱わない。

保存先はnoBackupFilesDir内の回答ごとのファイル。既存のCredentialVaultのAES-256-GCM／Android Keystoreを、認証用とは別の鍵aliasで再利用する。AtomicFileで書き、同じIDのファイルは上書きしない。復号後も保存IDを照合し、取り違えを拒否する。バックアップは既存のallowBackup=falseと除外設定に加えてnoBackupFilesDirで除外される。パスワード・token・認可URL・人格や過去の回答を保存レコードへ追加しない。

通常の手動生成では通知せず、保存成功後は短文と「回答の詳細を開く」を表示する。詳細には全文、生成日時、実際の使用データを表示し、健康値がなければ「健康データ未取得」と明記する。データを取得し直さないので、後から別の回答や新しい測定が増えても内容が変わらない。通知権限もChatGPTへの接続も、保存済み詳細の読み取り条件にはしない。保存に失敗した場合は通知・保存済み詳細を無効にし、保存失敗を表示したうえで生成済み全文は現在のアプリ画面に残す。

今回の保存は通知と詳細のために必要な範囲。履歴一覧と個別・一括削除は実装しない。保存済み回答は画面を離れたり接続解除したりしても残る。読み取り不可・鍵消失・ファイル欠損時は固定のエラーと再読み込みを表示し、別の回答へ切り替えたりAIで作り直したりしない。

## 明示的な検証通知だけ

詳細画面の「通知を試す」は保存済み回答を読むだけで、生成処理・HTTPクライアント・Health Connectとは接続しない。追加AI送信、自動再試行、定期実行、バックグラウンドAI通信はない。

- Android13/API33以上では、この操作時だけPOST_NOTIFICATIONSを要求する。起動時・通常の生成時には要求しない。拒否しても全文と使用データをその場で読める。
- API26〜32では実行時権限要求は不要。全バージョンでアプリ／通知チャンネルが無効なら通知せず、その状態を表示する。
- 通知チャンネルは「励ましの検証通知」。通知のタイトルは固定で、本文と展開本文は安全な短文のみ。全文、健康値、使用データ、生成プロンプトをNotification extrasに入れない。
- visibilityはPRIVATEを指定し、ロック画面表示・音・チャンネル設定はAndroid側の設定に従う。設定を強制変更したりバイパスしたりしない。
- 通知のtagと、immutableなPendingIntentのdata URIに回答UUIDを使用する。明示的にMainActivityだけを開き、Intentには健康値や回答本文を入れない。後の通知Bが通知Aの遷移先を上書きしない。初回起動とsingleTaskのonNewIntentを両方扱う。
- 通知タップ先のIDだけを保存状態に保持し、回転等でも同じ回答を読み直す。IDの形式・action・scheme・host・query／fragmentなしを検証する。外部URI用の新しい公開Intent filterは追加しない。

毎日の無操作AI生成は、SIWCの利用条件と非表示時通信を確認してから別途検討する。このPRは対応・許可・実機成功を主張しない。

## Androidだけでの実機試験

1. PRの最新CI成功とAPKのビルド識別子を確認し、Artifactsの **hagemashi-diagnostic-apk** を取得する。ZIPを展開しapp-diagnostic.apkを既存の「hagemashi 診断」へ上書きする。アンインストールや署名鍵の再生成は不要。
2. 既存の接続を使い、「実データで手動生成」で目標を入力し、送信前表示を確認して回答Aを生成する。**この通常生成では通知も通知権限ダイアログも出ないこと**を確認する。
3. 「回答の詳細を開く」で全文、生成日時、使用した値、測定日時／集計期間を確認する。健康データ未取得で生成した回答では、その明記と欠損理由も確認する。
4. 「通知を試す」を押す。API33以上なら最初は通知権限を拒否し、通知されないこと、引き続き詳細全文が読めることを確認する。次にAndroidのアプリ通知設定で許可し、**再度このボタンを明示的に押す**。許可しただけでは自動通知しない。API32以下はアプリ／チャンネルの設定で同様に確認できる。
5. 通知の折りたたみ・展開表示を確認し、短文だけで体重・体脂肪率・歩数・目標などの具体的な数値がないことを確認する。固定文への差し替えは正常。Androidが表示する時計・通知件数等は健康値ではない。ロック画面でも端末の設定どおりであることを確認する。
6. Aの通知はまだタップせず残す。アプリへ戻り、目標を変えるなどして回答Bを生成する。Bの通常生成でも通知が増えないことを確認する。
7. 最近使ったアプリからhagemashiを閉じ、残しておいたAの通知をタップする。**開くのはAの全文・生成日時・使用データで、Bではないこと**を確認する。サインインやAI送信を要求されないことも確認する。OSの「強制停止」は通知自体を取り消すことがあるため、この終了試験は通常のタスク終了で行う。
8. 任意でBでも「通知を試す」を押し、A/Bを別の通知としてそれぞれ開けることを確認する。画面回転後もその回答であることを確認する。

合格条件は「通常生成では通知なし」「通知に測定値なし」「タスク終了後もタップで該当回答の全文と数値を開ける」。報告はビルド識別子と各項目の成否だけでよい。実際の測定値、目標、回答、アカウント情報の貼り付けやスクリーンショットは不要。

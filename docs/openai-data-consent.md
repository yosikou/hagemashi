## 送信内容と操作

実装の `HealthReader` → `prepareGeneration` → `healthGenerationInput` / `generationRequest` を照合しました。

- 体重・体脂肪率は取得基準時点より30×24時間、歩数は現地日付で7日分。各記録の値・単位・測定日時、歩数の集計期間・提供元、取得状況・一部取得の表示を含みます。取得元の件数制限は維持します。
- 朝の基準は当日の現地午前0時で、当日の記録は含みません。夜・手動は取得時点を基準とし当日を含めます。
- 目標体重・任意の期限、維持の指定、使用人格のプロンプト、共通補足、言語・単位・朝夜手動の生成指示を、選択したモデル宛てに送ります。人格名は保存用であり、別の構造フィールドとしては送信しません。ユーザーが名前をプロンプトに書いている場合はその原文の一部として送信されます。
- 過去の励ましは送りません。未取得をゼロ・推測値で補いません。健康データなしでも目標・指示で生成可能です。
- 送信先はOpenAI `api.openai.com`。接続済みのChatGPTアカウントを使います。APIキーへの変更はありません。

起動時には同意画面を表示しません。設定を初めて開くと6言語の説明を表示し、表示済みバージョンを記録します。「今は送信しない」でも設定・履歴・バックアップを使用でき、設定→OpenAIへのデータ送信で後から同意できます。Health Connect権限・ChatGPTログインは別操作です。同意からアプリ内のプライバシー説明ページを開け、同ページからOpenAIの[プライバシーポリシー](https://openai.com/policies/privacy-policy/)も開けます。

同意後、ホームの「手動で作成」は追加の確認なしに取得・送信します。「送信するデータを確認（任意）」は従来の概要・全データ・プロンプト確認を残し、ここからの生成はその凍結した内容を送ります。再試行も同じ内容です。自動開始の実行済みフラグだけを画面再作成時に保持し、回転やプロセス再作成だけで手動リクエストを再送しません。健康データ・プロンプトはSavedStateに入れません。通常手動生成では通知しません。朝夜は同意だけでは有効にならず、通知設定で自動生成と使用枠を有効にした場合だけ実行します。

## 保存・停止・更新・復元

同意した説明版、表示済み版、移行版を既存の端末内暗号化設定に別々に保存します。未同意・旧版・未来版・不正な版・読み取り失敗では閉じた状態となります。`DATA_CONSENT_VERSION` を送信先・目的・データ項目の重要変更時に上げてください。旧版の同意は直ちに無効で、設定初回表示で再説明します。翻訳だけの変更は自動で同意版を変更しません。

既存版からの更新は、時刻とその他の設定・履歴を保持し、自動生成をオフに移行します。同意後も明示的にオンにするまで再開しません。保存済み回答の閲覧・通知タップには同意を求めません。

全生成経路（手動実データ・朝・夜・診断用ダミー・人格比較）を `ConnectionRepository.generate` に集約し、開始時に保存済み同意を確認します。さらに `Http` が本文を書き出す直前に `GenerationSendGate` が設定を読み直します。同意更新／停止／復元と同じデータロックで確認と書き込みを直列化します。生成リクエストは固定長ストリーミングを使用し、HttpURLConnectionの既定バッファが本文をロック解除後のHTTP状態取得まで保留しないようにします。OAuth等の送信方式・TLS・DNS・タイムアウトは変更しません。朝夜は自動生成オン、該当枠オン、予約世代も再確認します。DNS・OAuth更新・モデル取得の待機中に停止・取り消しが保存された場合も本文を書き出しません。予約の開始・当日・有効時間は既存の予約側で別途確認します。

設定→OpenAIへのデータ送信の「自動生成を停止」は同意を残し手動生成を許可します。「送信同意を取り消す」は手動・朝夜とも止め、自動生成もオフにします。保存前にすでに送信したデータを回収する機能ではありません。送信中の本文書き込みと設定保存のどちらが先に確定したかで順序が決まり、表示操作だけで送信済みデータが撤回されたとは報告しません。

バックアップから同意・表示済み状態・自動生成／朝夜枠の有効状態を除外します。旧形式のバックアップ内の有効フラグは受け入れても無視します。復元の原子的な設定切替で同意と表示済み状態をリセットし、予約は停止します。再開確認だけでも自動生成はオンになりません。新端末で再同意、接続・Health Connect／通知権限と時刻を確認し、再開確認後に通知設定で自動生成・使用枠を明示的にオンにしてください。保存済みの目標・時刻・言語・単位・人格・履歴は引き継ぎます。

## 検証とAndroid手順

開発環境に実機はありません。以下はユーザーがAndroidで実施する項目です。自動試験の結果はPRに記載し、CIでUIテストAPKをビルドしたことを実行成功とは扱いません。実アカウントの試験は利用枠を消費します。測定値・送信内容・回答・認証情報は診断やPRへコピーしないでください。

1. **新規／更新**：既存版を消さず同じ種類のAPKを更新。起動では同意画面が出ないことを確認。以前の朝夜時刻を記録していた場合、時刻が保持され自動生成がオフであることを確認。設定を初めて開き説明が出ることを確認。
2. **後で同意**：「今は送信しない」を選ぶ。目標・人格・履歴・バックアップを使えること、設定へ再度戻っても説明が自動表示されないことを確認。ChatGPT接続済み・目標／モデル設定済みでも「手動で作成」は送信せず同意設定へ案内することを確認。任意確認からも未同意で生成できないことを確認。
3. **手動**：設定内から説明とプライバシーページを読み、同意する。同意だけで自動生成がオンにならないことを確認。「手動で作成」を2回試し、追加の同意／送信確認操作なしに回答・履歴を取得できることを確認。任意確認では概要・全データ・人格指示を閲覧し、そこから生成できることを確認。通常手動通知は出ないことを確認。
4. **朝夜**：自動生成と使用する朝／夜枠をオンにし、保存済み時刻で実行する（時刻変更時は既存の予約世代が更新される）。ホームへ離れた状態／スワイプ終了状態を別々に試す。朝は前日まで、夜は当日の記録を使うこと、履歴追加・通知・タップ先の回答が一致することを確認。Androidの予約時刻は目安です。
5. **停止**：未来の枠を予約後、「自動生成を停止」。再試行待ちがある場合も実行時に新たな回答が増えないことを確認。同意が有効なら手動は引き続き成功することを確認。自動生成を再びオンにするまでは再開しないことを確認。
6. **取り消し**：設定で送信同意を取り消す。手動は案内になり、朝夜も新しい回答を作らず、既存履歴は読めることを確認。再起動後も同じ状態であること、設定へ戻るたびに説明が強制表示されないことを確認。
7. **復元**：同意済み・朝夜オンの端末で新しいバックアップを作り、復元。設定・時刻・任意履歴は戻る一方、同意と有効状態は戻らないことを確認。再開確認前／再開確認だけでは自動送信せず、設定を初めて開くと説明が出ることを確認。同意してから自動生成・使用枠を明示的にオンにする。#17の旧形式バックアップでもフラグが引き継がれないことを確認。
8. **6言語**：日本語、英語、フランス語、ドイツ語、ヒンディー語、簡体字中国語で説明・ボタン・状態・エラー・ポリシーページを確認。長文はスクロールでき、同意／拒否／戻るへ到達できることを確認。翻訳の自然さは未評価です。

ストレージ読み取り失敗、重要版変更による再同意、通信準備と取り消しの競合は、データを送らないJVM試験で確認します。一般利用者の端末データやネットワーク設定を壊して再現する手順は用いません。実端末での競合タイミング、破損した設定、再同意版への更新は未確認です。認証・モデル一覧取得は健康データ送信ではなく、別の利用者操作で行う既存フローを維持します。

# AdMobテストバナー（診断版のみ）

2026-11-17に次のGoogle公式資料を確認しました。

- [Android導入](https://developers.google.com/admob/android/quick-start)：`com.google.android.gms:play-services-ads:25.5.0`、minSdk24以上、compileSdk35以上。現行のminSdk26／compileSdk36／JDK17・Gradle8.11.1・AGP8.10.1・Kotlin2.2.21を維持し、CIで互換性を確認します。公式ではこの系列をLegacyと呼び、別系列のNext-Genへの移行案内もあります。本PRは示した依存1つだけを採用します。
- [リリースノート](https://developers.google.com/admob/android/rel-notes)：25.5.0の変更とAPI下限を確認。
- [テスト広告](https://developers.google.com/admob/android/test-ads)：Googleのデモ広告ユニットであり、本番アカウント・IDや端末ID登録は不要です。
- [バナー](https://developers.google.com/admob/android/banner)：画面幅を指定する適応バナー、メインスレッドのloadAd、画面を離れた後のdestroyに従います。
- [パーソナライズ無効化](https://developers.google.com/admob/android/targeting#publisher_privacy_treatment_beta)：PPTを初期化前にDISABLEDへ設定します。これを利用者の広告同意が得られたという扱いにはしません。
- [SDKの自動収集情報](https://developers.google.com/admob/android/privacy/play-data-disclosure)：SDKはIP・操作・診断・識別情報等を自動収集し得ます。テスト広告も「通信や技術情報の収集が一切ない」という意味ではありません。

## 表示とデータ分離

`diagnosticImplementation` と診断版専用Manifest／ソースにSDKとIDを閉じ込めます。通常のdebugとreleaseは空のスロット実装にし、SDKを依存に含めず、広告の初期化や読み込みをしません。実際に配布するdebug／diagnosticのAPKをCIで検査し、debugにSDKがないこと、diagnosticに正しいデモ設定がありAD_ID／AdServicesの追加権限がないことを検査します。Androidの既存INTERNET／ACCESS_NETWORK_STATEは使います。

通知・履歴の両方が既存の同じ回答詳細へ遷移します。本文・使用データを既存のスクロール領域に先に表示し、その外側の下部に1つのバナーを配置します。画面幅から左右の安全領域を除いたdp幅でlarge anchored adaptiveサイズを求め、下端のシステム領域も避けます。本文や戻るボタンへ重ねません。画面幅変更時には古いAdViewを破棄します。

SDK初期化をバックグラウンドで1回だけ行い、本文の読み取り・表示とは待ち合わせません。初期化待ちは35秒、広告待ちは45秒まで。読み込み中は高さ0、失敗・タイムアウト後はAdViewを取り除き、空枠やエラーカードは残しません。成功時だけ広告の高さを確保します。広告待ちでもスクロール・戻るを使えます。画面破棄や失敗時にAndroidViewのonReleaseでdestroyし、リスナーを外します。pause／resumeも画面ライフサイクルに従います。アプリ側の自動再試行ループは追加せず、読み込み失敗後は詳細を開き直して再試験できます。SDK初期化自体が失敗した場合はアプリプロセスを開き直して再試験します。

広告コンポーネントに回答・健康値・設定・認証情報・回答IDを渡す引数はありません。SDKにはApplication Contextと広告サイズ、固定のテストID、パーソナライズ無効設定だけを使い、AdRequest.Builder().build()でリクエストします。キーワード、content URL、周辺コンテンツURL、カスタムターゲティング、ネットワークextras、publisher ID等は設定しません。WebView登録、Firebase連携、広告メディエーションは追加しません。体重・体脂肪率・歩数・目標・人格・補足・本文・ChatGPT認証情報を広告SDKへ渡す処理はありません。SDKエラーや生のレスポンスをアプリの診断へコピー・記録しません。SDK自身の技術ログ／自動収集は別であり、実通信のパケット監査は未実施です。

OpenAIの同意状態は広告コンポーネントから読みません。拒否済みでも保存済み回答を読め、診断版では同じテストバナーを試せます。OpenAIの同意を広告の同意として扱いません。本番配信に必要な広告同意・データ開示等の対応を完了したとは報告しません。

## Androidだけでの実機確認

APKリンクとCI結果はPRに記載します。GitHubにログインしたAndroidブラウザで診断版のZIPを取得・展開し、`app-diagnostic.apk` をインストールします。同じ署名の既存診断版は上書き更新し、既存アプリのアンインストールは不要です。通常版と診断版のデータは別です。通常版APKは広告非搭載の比較用です。

1. **履歴から**：診断版の保存済み回答を履歴から開く。本文・当時の人格・日時・使用データを先に読めることを確認。その後、下部にGoogleのテスト広告表示が1枠だけ現れることを確認。実広告ではないことを確認し、テスト表示がない広告は操作せず報告してください。広告のクリックは合格条件に含めません。
2. **通知から**：その回答の詳細にある「通知を試す」で生成済み回答の通知を出す。この操作はChatGPTへ追加送信しません。アプリを離れて通知をタップし、同じ回答と短文タイトル、本文、下部のテストバナーを確認。後から別の回答を作っていても、古い通知は元の回答を開くことを確認。
3. **本文と戻る**：広告が読み込み中の間にも本文をスクロールし、使用データを展開・折りたたみ、戻れることを確認。表示後も本文や操作ボタン・Androidナビゲーションへ重ならないこと、縦画面・横画面・分割画面で幅をはみ出さないことを確認。
4. **オフライン**：端末を一時的に機内モードにし、保存済み回答を履歴や残っている通知から開く。OpenAIへの生成操作は不要。本文をすぐ読め、広告の空枠を残さず、スクロール・戻るができることを確認。通信を戻して詳細を開き直し、テストバナーを再確認。
5. **重複・破棄**：詳細→履歴→同じ詳細、別の回答、通知からの詳細を繰り返す。広告は常に最大1枠で、古い広告が下に追加され続けないことを確認。画面回転とホームへ離れて戻る場合も確認。
6. **同意の分離**：OpenAIへの同意を拒否・取り消した状態で、既存の回答詳細とテストバナーを開けることを確認。広告を見ることによってOpenAIの同意が有効にならず、未同意の新規手動生成が止まることも確認。
7. **通常版**：通常版の同じ履歴／通知詳細では広告も空枠も出ず、本文・スクロール・戻るが従来どおりであることを確認。

履歴がない診断版では、先行PRのバックアップ・復元で保存済み回答を移すか、送信同意後に1件だけ手動生成して準備します。実データや回答をPR・スクリーンショット・診断ログへ載せないでください。

実機のGoogle配信、オフライン失敗、各Androidバージョンのレイアウト、通知／履歴の実操作、SDKの実通信内容は未確認です。CIのAPK生成やUI試験コンパイルを実機合格とは扱いません。

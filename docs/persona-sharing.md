## JSON形式・制限

UTF-8で次の3項目だけを持つ1人分のオブジェクトです。

```json
{
  "formatVersion": 1,
  "name": "友人のようなトレーナー",
  "prompt": "優しく励ましてください。\n欠損値は推測しないでください。"
}
```

- 最大64KiB（65536バイト）。名前は120、プロンプトは12000 Unicodeコードポイントまで。空／空白だけの名前・プロンプトは拒否します。
- formatVersionは整数の1。必須項目の欠落、文字列でない名前／プロンプト、余分な項目は拒否します。
- JSONコメント、単一引用符、末尾カンマ、重複キー、末尾の余分なデータ、不正UTF-8、不正なUnicodeサロゲートも拒否します。UTF-8 BOMは受け付けます。
- AndroidとJVMのorg.jsonパーサーの寛容さに依存せず、読み込むバイト数を制限してから厳密に構文を検証します。極端な入れ子も拒否します。
- 共有ファイルにID、初期／編集済み区分、共通補足、認証、目標、測定値、履歴、アプリ設定は追加しません。JSONのインデントやフィールド順自体は往復保証の対象ではありません。名前とプロンプトの文字列・改行・前後の空白は保持します。

## 操作と保存

設定→人格の各カードに「この人格をエクスポート」を置きます。使用中の選択とは独立して任意の1人を選べます。Android標準のCreateDocumentで保存先を選びます。ファイル名の初期値は `hagemashi-persona.json`、MIMEはapplication/jsonです。出力対象を押した時点の名前・プロンプトを固定します。

未編集の初期人格は、その時点の表示言語の既定の名前とプロンプトを出します。編集済みの初期人格／カスタム人格は、アプリが現在実際に使用している原文を出し、勝手に翻訳しません。補足欄や他の設定からテキストを混ぜません。

「人格をインポート」でAndroid標準のOpenDocumentからファイルを選びます。JSONとして配布するプロバイダーに加え、text/plainとapplication/octet-stream扱いのファイルも選択可能にし、拡張子・MIMEに頼らず内容を検証します。検証後は名前とプロンプト全文をスクロールして確認でき、まだ設定は変更しません。「カスタム人格として追加」の確認でのみ、新しいUUID・defaultContent=falseの人格を追加します。同名の人格を上書きせず、選択中のIDも維持します。名前とプロンプトをトリム・翻訳・改行正規化しません。

キャンセル、ファイル選択の中止、検証失敗では設定を保存しません。保存に失敗した場合はプレビューとそのIDを保持して再試行します。同じプレビューの再試行で同一IDを二重追加しないようにします。もう一度ファイルを選び直して追加すると別IDの新しい人格になります。

読み書きはIOスレッドで行い、処理中の重複操作を防ぎます。回転によるActivity再作成ではViewModelに保持した対象とプレビューを使います。プロセス消失でエクスポート対象が失われた場合は別人格を保存せず失敗として案内し、再度エクスポートします。保存先作成後の書き込み失敗では不完全なファイルが残る場合があり、自動で既存ファイルを削除しません。

共有操作からChatGPT／Health Connectを呼び出しません。確認後の設定保存でも予約の再登録は行わず、AI生成・通知を起動しません。すでに設定済みの朝夜予約は、その予約時刻に通常どおり動作します。URIやファイル本文、プロンプト、生の例外メッセージはログ・診断に出しません。ファイル権限は標準ピッカーの一時的なURIアクセスを使い、追加のストレージ権限・永続URI権限・依存ライブラリは不要です。minSdk26で利用できるAPIのみです。

## Androidだけでの試験

1. 本PRの成功したActions実行から通常版hagemashi-debug-apkまたは別IDのhagemashi-diagnostic-apkを取得します。ZIPを展開して更新インストールし、既存アプリは削除しないでください。#15の多言語対応もこのAPKに含まれます。
2. 設定→人格で、現在の選択と既存の名前・プロンプト・共通補足を確認します。初期人格1人の「この人格をエクスポート」を押し、Androidの保存画面でDownloads等へJSONを保存します。初期人格・カスタム人格それぞれで試してください。
3. 保存したファイルをAndroidのテキスト表示アプリ等で開き、3項目だけで共通補足・目標・認証・測定値・履歴がないことを確認します。未編集の初期人格はエクスポート時の表示言語であることを確認します。
4. 「人格をインポート」でそのファイルを選び、確認画面で名前と複数行のプロンプトの全文を読みます。まずキャンセルし、人格数・内容・選択が変わらないことを確認します。ファイル選択画面自体を中止する場合も確認します。
5. 再度選び「カスタム人格として追加」を押します。同名でも別カードが追加され、既存内容と使用中の選択は変わらないことを確認します。追加した人格を再エクスポートし、名前と改行、前後の空白が保たれていることを確認します。
6. [多言語のサンプル](persona-examples/multilingual.json)をGitHubのファイル画面のダウンロード操作で端末へ保存します。アプリをドイツ語や英語にして取り込み、名前・日本語／フランス語／ヒンディー語／ドイツ語の複数行プロンプトが原文のままであることを確認します。別言語へ切り替え、再起動しても原文が保持されることを確認します。
7. [不正JSON](persona-examples/invalid-json.json)、[未対応バージョン](persona-examples/unsupported-version.json)、[必須項目不足](persona-examples/missing-prompt.json)、[プロンプト上限超過](persona-examples/too-long-prompt.json)をダウンロードし、取り込み時にそれぞれ異なる理由が表示され、プレビューの追加操作へ進めず設定・選択・人格数が変わらないことを確認します。
8. JSONファイルそのものの64KiB超過は、TermuxにPythonがある場合、次の操作で検証できます。作成したファイルをOpenDocumentから選び、サイズ超過となることを確認します。

```sh
python -c 'from pathlib import Path; Path("too-large-persona.json").write_bytes(b" "*65537)'
```

9. 6言語で、エクスポート・インポート・確認・キャンセル・各エラーの文言が切り替わることを確認します。長いドイツ語のラベルやヒンディー語の文字が切れないこと、プレビューが全文スクロールできることを確認します。
10. ファイル選択中／プレビュー表示中に画面を回転し、別人格を出力したり自動保存したりしないことを確認します。取り込んだだけで生成画面への遷移・ChatGPT通信・新しい回答や通知が発生しないことを確認します（切り分け時は朝夜予約をオフにして試してください）。

## 検証範囲

JVMでJSON往復、原文と改行、3項目の制限、同名追加と選択維持、別言語でも原文保持、キャンセル相当の未確定読み込み、不正ファイルの分類、上限ちょうど／超過、長さ不明ストリームの読み取り制限を検証します。Android UI試験APKには全文確認・言語変更後の原文保持・キャンセルで確定しない試験を追加します。MainActivityTestも確認しています。

開発環境にAndroid端末は接続していないため、標準ファイル選択画面・実ファイルの保存と取り込み・回転の実機確認は未実行です。UI試験APKのコンパイルは実行成功ではありません。必須Gradleはローカルの配布ZIP取得が通信制限で失敗するため、GitHub ActionsでLint・単体テスト・APKビルド・継続署名を確認します。設定・履歴の暗号化バックアップ／復元は対象外です。マージはレビュー後です。

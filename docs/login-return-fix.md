# 通常のブラウザ認証後にアプリへ戻って接続を完了する

## 実機で分かったこと

CUBOT TAB KINGKONG S／Android15／モバイル回線で、アプリ表示中のDNS・GET・空POSTは成功した。通常のブラウザ認証ではcallback後、アプリ非表示中の名前解決とコード交換が失敗し、アプリ復帰時はDNS成功。分割画面で表示を維持すれば接続成功した。省電力OFF・VPNなし、アプリのバックグラウンド通信と動作を許可する設定だった。端末／OS内部の制限の根本原因は未確定。

従来はcallbackを受けるとブラウザ表示中にコード交換を開始し、ユーザーが戻る前に失敗を確定させていた。今回、callback受信と外部ネットワーク処理を分離する。認証中の常時表示や分割画面を必要としない。

## 変更後の流れ

1. 通常のContinue with ChatGPTから外部ブラウザを開く。アプリは非表示でよい。
2. 公式のloopback callbackを受信してstate等を検査し、ブラウザに「アプリへ戻って接続を完了」を表示。loopback listenerはこの時点で閉じる。
3. 認証情報を含まない戻るリンクをユーザーが押す。あるいは最近使ったアプリから戻る。
4. 既存MainActivityが再開すると、待機中の同じ認証処理がコード交換・署名鍵取得・ID token検証・暗号化保存を続ける。認可コード交換を自動再試行しない。接続完了まで数秒はアプリを開いておく。

外部ネットワーク処理の前にonResumeでの復帰を確認する。途中で再び離れた場合、次の通信開始を復帰まで待つ。既に開始したリクエストの中断・自動再送や、バックグラウンド通信の継続保証はしない。

待機は既存の認証全体5分の期限・キャンセルに従う。期限切れやOSによるプロセス終了では新しくサインインする。認可コード・state・nonce・PKCE情報を戻るリンク、Intent、診断、ログ、ディスクへ追加保存しない。コードのサーバー側有効期限を延長するものではないため、ブラウザ認証後は速やかに戻る。

## 方式と安全性

[公式SIWCの認可フロー](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)の認可URL・loopback redirect・PKCE・nonce・ID token検証を変更しない。戻るリンクは別の認可callbackとして使わず、画面を開くためだけに使用する。Deep linkからコード交換の材料や接続状態を受け取らない。

[Chrome公式のAndroid Intent](https://developer.chrome.com/docs/android/intents)に沿ってユーザー操作による固定のintentリンクを置く。通常版／診断版それぞれのpackageを明示し、singleTaskで既存Activity／ViewModelへ戻す。自動で画面を奪う処理やJavaScript redirectは加えない。ブラウザによってリンクで戻れない場合も、手動でアプリへ戻れば同じ処理を再開できる。

追加サービス・通知・権限、DNS変更、固定IP、ネットワーク固定、プロキシ変更、Cookie流用、APIキーへの変更はない。暗号化保存・バックアップ除外・継続署名・診断版の別IDを維持。回答生成のPROTOCOL_ERRORは今回の変更対象ではない。

## 実機再試験

1. 最新のhagemashi-diagnostic-apkを、既存の「hagemashi 診断」へアンインストールせず上書き。既存の通常版も残す。署名Secretは変更・再生成しない。
2. 接続済みなら接続解除を行い、通常の全画面でContinue with ChatGPTを押す。分割画面は使わない。
3. ブラウザで認証完了後、数秒ブラウザに留まってから「アプリへ戻って接続を完了」を押す。戻る前の認証受付ページは接続完了を意味しない。
4. アプリ復帰後に「接続済み」となり、認証中に非表示だったことだけを理由にコード交換が失敗しないか確認。
5. 別試行で、リンクを使わず最近使ったアプリから戻っても接続完了するか確認。
6. 接続完了後、アプリを閉じて開き直し、接続維持と接続解除を確認。
7. 可能なら、認証完了後すぐ戻らず5分を超えた場合や待機中のキャンセルで接続されず、新しいサインインからやり直せることを確認。古いコードを再利用しない。

スクリーンショットは診断部分だけ。ブラウザのアドレス欄、認可コード・token・アカウント情報、端末識別子は不要。失敗時は処理段階・固定分類・HTTP状態・許可済み例外クラスだけを報告する。

## ユーザー実機結果と採用

ブラウザから戻るサインイン、モデル一覧取得、固定プロンプトの回答表示、アプリを完全に閉じて開いた後の再ログインなしの生成、接続解除後の生成禁止はユーザーが確認済み。この手順を標準採用し、上記3点の再試験は求めない。[確認したAPKと検証範囲](chatgpt-device-acceptance.md)を参照。トークン更新、サーバー側失効、端末OS再起動、全てのブラウザでの復帰は未確認。

# ブラウザを閉じてアプリへ戻り、接続を完了する

## 標準手順

1. hagemashiで「Continue with ChatGPT」を押し、外部ブラウザで認証する。
2. 「認証結果を受け付けました。接続はまだ完了していません」と表示されたら、**そのブラウザのタブを閉じる**。
3. hagemashiへ戻る。タブを閉じても別のブラウザタブが表示される場合は、最近使ったアプリからhagemashiを開く。
4. アプリが再開すると、待機していたコード交換・署名鍵取得・ID token検証・暗号化保存を続け、「接続済み」になる。

分割画面やブラウザ内のアプリ復帰リンクは使わない。ブラウザを強制停止する必要はない。callback受信前にタブを閉じた場合は接続を完了できない。認証全体は5分以内で、受付後は速やかに戻る。

## 実機結果と今回の修正

ユーザーはブラウザから戻る認証、モデル一覧・固定プロンプトの回答表示、アプリを完全に閉じて再度開いた後の再ログインなしの回答取得、接続解除後の生成禁止を確認した。その後、成功した標準手順は「ブラウザを閉じて戻る」方法であると明確化した。これを採用する。

PR #4取り込み時の文書は復帰リンクを標準として記載していた。今回、受付ページからintentリンクを削除し、ブラウザのタブを閉じる案内に統一した。不要になったauth-return用Intent filterとリンク生成も削除した。外部ブラウザを開く処理、callback受信、onResume待機、コード交換・本人検証・暗号化保存・生成は変更しない。

確認済み3項目の一括再試験は求めない。変更後の受付ページの案内と、タブを閉じた後の復帰UIは新APKでは実機未確認である。トークン更新・サーバー側失効・端末OS再起動・全ブラウザへの適用も未確認。[実機受け入れ記録](chatgpt-device-acceptance.md)を参照。

## 処理と安全性

端末では、アプリ表示中のDNS・HTTPS通信は成功する一方、callback後の非表示中はDNS失敗、復帰時はDNS成功だった。端末／OS内部の根本原因は未確定。既存のLoginReturnはcallback受信後、MainActivityのonResumeまで外部ネットワーク通信を待つ。この待機を維持し、認可コードを自動再送しない。途中で再び離れた場合も、次の通信開始を復帰まで待つ。

[公式SIWCの認可フロー](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)のloopback callback・PKCE・nonce・ID token検証を維持する。ブラウザを閉じる操作は画面の復帰だけであり、認証結果をIntent等で渡す別方式ではない。認可コード等はメモリ内だけに保持し、ページ・ログ・診断・ディスクへ追加保存しない。受付ページは静的な案内だけで、JavaScriptによる自動終了・自動遷移はしない。通常のブラウザタブをアプリから強制終了できるとは扱わない。

期限切れ・キャンセル・認証途中のプロセス終了では新しくサインインする。コードのサーバー側有効期限を延長しない。追加サービス・通知・権限、DNS変更、固定IP、ネットワーク固定、Cookie流用、APIキーへの変更はない。Keystore保護・バックアップ除外・継続署名を維持する。

単体テストは、非表示中のコード交換待機、復帰後の1回だけの交換、再度離れた場合の待機、キャンセル・期限切れ、受付ページのHTMLエスケープとリンク／自動遷移なしを検証する。実機がない環境ではUI試験を実行済みと扱わない。

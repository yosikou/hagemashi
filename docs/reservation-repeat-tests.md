# 同じ日の予約再試験と結果表示

ユーザーの指示により、通常の励まし通知・保存済み回答の検証通知の「同日同枠1回」という上限を解除する。予約ごとの通信再試行による重複防止は維持する。期限切れ再設定案内の1日1回・合計最大3回は別のルールとして維持する。

## 識別と旧記録

予約は現地日付・朝夜枠・予約世代で区別する。時刻変更、オフ→オン、モード変更などで世代が変わり、同じ日でも新しい予約になる。何も変更していない同じ予約を繰り返し実行し続けるものではない。設定時刻を過ぎた後に何も変更せず翌日分が予約されるのは通常の日次予約である。

以前の日付＋枠だけのclaimsは通常の予約成功の判定に使わない。残っていても当日の新しい予約を翌日へ送らない。既存の回答・認証・設定・削除記録は消さず、古い回答は従来のIDで閲覧できる。期限案内の制限も消さない。

新しい回答IDと通知タグは日付＋枠＋世代に対応する。通信再試行では同じIDを使い、保存されていればAIへ再送しない。時刻を変更した新しい予約は別IDとなり、当日でも新しい回答を履歴に1件保存する。以前の通知も、その通知を出した回答を開く。

## 保存と通知

- 生成した回答を暗号化保存し、履歴索引を確認してから通知する。
- 通知権限がなくても、自動モードの予約・生成・履歴保存は停止しない。通知だけを当日の有効時間内に再試行する。
- 日付・枠・世代ごとに、回答IDとSAVED / SENDING / POSTED / BLOCKED / FAILED / GENERATION_FAILED / SKIPPED / UNKNOWNを保存する。
- 画面は「回答保存済み・通知発行済み」「回答保存済み・通知不可／再試行待ち」「生成失敗」「生成スキップ」「通知状態未確認」を区別する。発行済みは通知APIの結果で、画面への到着を保証しない。
- 通知だけ失敗した場合は、同じ暗号化回答を読み、AIへ再送せず同じ通知タグで再試行する。
- 通知発行中のプロセス終了は結果不明になり得る。次回、対象通知がOS内でactiveなら発行済みと記録し、それ以外は通知状態未確認にする。消された通知を自動で再発行して二重通知することは避ける。新しい予約としての再試験は可能。
- 削除済み回答は再作成せずスキップと表示する。保存済みと記録されていても本文を読めない場合は、その状態を表示する。

## Androidだけの再試験

1. 修正版診断APKを上書きする。アプリデータ・認証・履歴を消す必要はない。
2. 設定→通知で自動生成がオンであることを確認。他方の枠をオフにし、試す枠の時刻を現地の数分先へ変更する。朝夜を両方オンにする場合は朝＜夜を守る。
3. 予約診断のREGISTER_RETURNED／JOB_ENQUEUEDのtriggerが、当日の予定時刻であることを確認する。過去の「処理済み」だけで翌日へ送られないことを確認する。
4. ホームへ離れて待ち、履歴に新しい回答が1件追加され、通知から同じ全文を開けることを確認する。
5. 同じ枠の時刻をもう一度、現地の数分先へ変更する。翌日を待たず新しい回答がもう1件追加され、その通知も対応する全文を開くことを確認する。
6. 通知権限／チャンネルを無効にして、再び時刻を変更する。生成した回答が履歴に1件保存され、「回答保存済み・通知不可／再試行待ち」になることを確認する。有効時間内に通知を再許可し、同じ予約の再試行でAUTO_REUSEDとなり、履歴が増えずに通知が発行されることを確認する。時刻を変更すると新しい予約になるため、通知だけの再試行検証中は変更しない。
7. 再認証・モデル利用不可など生成できない場合は生成失敗と表示され、保存・通知成功と表示されないことを確認する。設定を直して時刻を変更し、当日に再試験できることを確認する。
8. ホーム離脱とスワイプ終了は別試験にする。未到着ならAPP_OPENより前後のJOB_STARTED／CHATGPT_COMPLETED／AUTO_SAVED・REUSED／NOTIFY_RETURNEDを確認する。新構成の実機合格はまだ確認していない。

今回の上限解除は、通信の再試行を無制限・翌日持越しにするものではない。朝の夜枠締切・当日末・手動生成との排他は維持する。実機未確認の条件は未確認と記録する。マージは行わない。

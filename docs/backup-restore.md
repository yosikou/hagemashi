## 保存対象

設定→バックアップと復元から、Android標準の保存先選択（CreateDocument）を使います。Google Driveは端末にあるDocumentsProvider経由で選びます。専用サーバー・Googleログイン・Google SDK・新しい権限は追加しません。

- 目標体重（kgの保存値）・期限・維持設定、言語・kg／lb、朝夜の時刻と有効設定、自動生成の設定、選択モデル・人格ID。
- 全人格の名前・プロンプト・既定／編集済み区分、カスタム人格、共通補足。編集済み内容とカスタムの原文は維持します。未編集の初期人格は選択言語に従う従来の扱いです。
- 履歴を含めるチェックは初期オフ。オンの場合、安定した回答ID、短文・本文、生成日時、生成時の人格名と朝夜手動区分、使用データ・測定日時・集計期間・欠損状況など、詳細に必要なスナップショットを含めます。

ChatGPTの認証ストアやトークン、端末Keystore鍵、現在のOS権限、予約台帳・実行待ちJob／Alarm・通知ID・予約バージョンは含めません。履歴中の「生成時に未許可だった」という取得状況は過去の説明として保存しますが、OS権限を復元・付与する情報ではありません。人格1人の公開共有は人格画面のJSON機能を使います。

## ファイル形式・暗号化

拡張子の初期値は `hagemashi-backup.hgbak`、MIMEはapplication/octet-streamです。ファイルを直接開くのではなく、アプリの「バックアップを選ぶ」から選びます。

バージョン1のバイナリ形式：magic `HGMBACK!`（8バイト）＋big-endian整数のバージョン1（4バイト）＋ランダムsalt（16バイト）＋ランダムnonce（12バイト）＋AES-GCM暗号文と128-bit認証タグ。40バイトのヘッダー全体をAADとして認証します。

鍵は利用者のパスフレーズからPBKDF2-HMAC-SHA256、600000反復、256-bitで導出し、AES-256-GCMで暗号化します。saltとnonceは毎回SecureRandomで作ります。形式バージョンにKDFパラメーターを固定し、ファイルの未認証値で反復回数を増やすことはありません。Android Keystoreでラップした端末依存の鍵は外へ出さず、別端末で同じパスフレーズにより復号できます。

パスフレーズは12〜256 Unicodeコードポイント、正規化・トリムせず入力をそのまま使います。作成時は2回一致を確認します。パスフレーズをファイルや設定へ保存せず、画面の自動保存状態にも入れません。処理後は扱ったchar配列を消去します。復元には同じパスフレーズが必要です。文字列や復号済み内容をログへ出さず、平文の中間ファイルも作りません。

ファイルは16MiB、履歴は5000件までです。圧縮は使わず、読み込みはサイズ情報なしでも上限+1バイトで停止します。大きすぎる場合は履歴なしで保存するか履歴を整理します。パスフレーズ誤りと認証タグ不一致（破損／改変）は暗号上区別できないため、共通の案内で表示します。

## 確認・原子的な復元

ファイル選択→パスフレーズ入力→復号・内容確認の段階では現在の設定と履歴を変更しません。対象設定と履歴件数を見て「設定を置き換えて復元する」で初めて反映します。設定は置き換え、既存履歴は保持し、バックアップ中の新しいIDだけ追加します。同じIDが既存にあれば既存の本文を優先します。同じファイルの繰り返し復元で同一回答が増えません。バックアップに含まれる削除済みIDは明示的な復元として戻せます。

復元時は新しい端末内保存世代に、既存の設定・履歴ファイルと履歴インデックスをコピーします。その中で設定を置き換え、履歴をマージし、読み直して検証します。各データは端末のKeystoreを使って保護されたままです。準備した各ファイルとディレクトリを同期し、最後に単一の世代ポインターを同じファイルシステム内のatomic moveで切り替えて親ディレクトリを同期します。確定後の同期でエラーになっても新世代が有効なら全体の反映は完了扱いとし、旧世代は掃除せず残して電源断時にも旧・新のどちらか一式を保持します。対応しないファイルシステムなら、非原子的な上書きへはフォールバックせず失敗として元のデータを保持します。

全SettingsStore／AnswerStore操作は共有ロックで保存先を操作ごとに解決するため、既に作られたViewModel・Storeも切替後の同じ世代を読みます。設定だけ先に見える状態は公開しません。設定準備・履歴準備・検証・確定前に失敗すると、新しい世代を使わず元の世代を維持します。プロセス中断前に確定していなければ旧世代、確定後なら新世代です。不要な古い世代や旧形式データは確定後に限定したパスだけを掃除し、認証・予約ストアは触りません。旧保存形式は読み込みますが、復元して世代化したデータを旧APKへ直接ダウングレードして読むことは対象外です。確定後のOS側の予約取消し失敗では、確定済みデータを「復元失敗」と誤表示しません。

反映中は進行中の生成と競合しないように待ち、自動生成はキャンセル・直列化します。確定後のローカル処理は途中キャンセルで半端にしません。それ以前の読込・暗号化・確認はキャンセルできます。保存先を作った後の書込失敗／中止で不完全な外部ファイルが残る場合は再作成してください。

## 予約を再開するまで

復元で朝夜と自動生成をオフにし、元の希望時刻・有効設定を別の再開待ち項目として保存します。ローカルで新しい予約世代番号を作り、古いJob・Alarmや取り込んだ自動回答IDを実行待ち状態として再利用しません。登録・Receiver・Jobの入口と純粋な予約判定でも再開待ちをチェックします。通常の通知設定の有効スイッチも再開までは無効です。古いOS予約が残っても生成・通知に進みません。

ホームとバックアップ画面に停止中の案内を表示します。朝夜時刻、再開後の自動生成設定を示し、ChatGPT・モデル・Health Connect・通知の設定へ案内します。認証やOS権限をバックアップから復元することはありません。現在の端末の認証は勝手に削除・サーバー失効しません。新端末では接続が必要です。

利用者が確認チェックと「朝夜の予約を再開する」を押した後にだけ再開待ちを解除し、保存された有効設定で新しく予約します。自動生成を使う有効枠ではChatGPT接続・目標・モデルを必要とし、通知権限も確認します。Health Connectが未許可でも健康データ未取得として生成できる既存の仕様を維持します。両枠ともオフなら権限や接続を強制せず確認を完了できます。

## Google Driveを使うAndroid実機試験

1. 本PRの成功したActionsから通常版または診断版APKのZIPを取得・展開して更新インストールします。既存アプリは削除しないでください。機種変更相当の試験は別端末、または未使用の検証用アプリID／プロファイルで行います。既存データがある復元先では設定を置き換えることに注意し、先にその端末のバックアップを作ってください。
2. 復元元で、目標と期限・言語・単位、朝夜時刻と有効設定、モデルと人格、編集済み初期人格・カスタム・共通補足を設定し、履歴の件数と詳細を確認します。再開の試験では、自動生成を有効にした設定をバックアップへ含めてから、比較対象端末の自動生成だけを止めると別の予約による履歴追加と切り分けやすくなります。
3. 設定→バックアップと復元で履歴をオフにし、12文字以上のパスフレーズを2回入力して作成します。Androidの保存画面のメニューからGoogle Driveとフォルダーを選んで保存します。Driveが表示されない場合はDriveアプリ／端末の提供機能を確認してください。hagemashi独自のGoogleログインはありません。
4. 履歴を含める場合でもう1つ作成し、別名にします。バイナリファイルであることを確認し、パスフレーズをバックアップと別に管理します。パスフレーズや実データ入りファイルをチャット・PRへ添付する必要はありません。
5. 復元先で「バックアップを選ぶ」→Google Driveから設定のみのファイルを選び、パスフレーズを入力します。対象設定と履歴0件を確認してまずキャンセルし、復元先の現在設定と履歴が変わらないことを確認します。ファイル選択自体を中止する場合も確認します。
6. 再度選び、復元を確定します。目標・期限・言語・単位・モデル・人格と原文の補足が移り、復元先の既存履歴は残ることを確認します。朝夜の時刻は表示されますが、再開待ちで生成・通知が始まらないことを確認します。アプリ終了・再起動後も停止中であることを確認します。
7. 履歴付きファイルを復元し、短文・本文・生成日時・人格名・使用データの表を開きます。同じファイルをもう1度復元し、履歴件数が増えず、同じIDの回答全文が変わらないことを確認します。復元先にも元々あった別IDの履歴が残ることを確認します。
8. 誤った12文字以上のパスフレーズで試し、固定のエラー案内と、現在の設定・履歴が変わらないことを確認します。ファイルの検証用コピーの末尾1バイトを変えた破損ファイル、ヘッダーのバージョンを変えたファイルでも同じく確認します。TermuxにPythonがある場合、読める作業ディレクトリにコピーして下記の操作で検証ファイルを作れます。

```python
from pathlib import Path
raw = bytearray(Path("test-backup.hgbak").read_bytes())
damaged = raw.copy()
damaged[-1] ^= 1
Path("damaged.hgbak").write_bytes(damaged)
unsupported = raw.copy()
unsupported[8:12] = (99).to_bytes(4, "big")
Path("unsupported.hgbak").write_bytes(unsupported)
```

9. 保存失敗の確認は診断版を使います。復元内容を確認した状態で、通常の確定ボタンの代わりに診断用の「設定の準備後」「履歴の準備後」「確定直前」の失敗ボタンをそれぞれ押します。元と異なる目標や新しい履歴を含むバックアップで試し、固定の保存失敗案内、現在の設定・履歴・言語の保持を確認します。これは同じ復元処理へIOExceptionを注入する試験で、実際に端末を容量不足にする試験ではありません。通常版には失敗ボタンはありません。
10. 正常復元後、新端末でChatGPTへ再接続し、利用可能モデルを確認します。Health Connectの読み取りと通知を許可し、バックアップ画面へ戻って時刻と再開後の設定を確認します。チェック・再開ボタンを押す前は通知が来ないこと、確定後にだけ有効枠が新たに予約されることを確認します。朝夜両方オフのバックアップも試します。
11. 再開後に朝夜の時刻を近い未来へ変更し、通知から対応する回答全文と使用データを開けることを確認します。復元前に届いていた古い通知も、復元先に元々あった回答を引き続き開けることを確認します。通常の手動生成と人格1人のJSON共有も使えることを確認します。
12. 6言語で作成・復号・確認・失敗・再開の文言が切り替わること、kg／lbと数値・日時表示が引き継がれることを確認します。Driveからの読み書き、画面回転、キャンセル時も確認してください。

## 開発側の検証と限界

JVMでPythonのhashlib／AESGCMで独立に生成した公開テストベクトルの復号、設定のみ／履歴付きの形式往復、公開鍵や端末鍵なしのパスフレーズ復号、salt／nonceの変更、誤パスフレーズ・改ざん・未対応版の拒否、実際の世代保存エンジンの設定準備／履歴準備／検証／確定前の失敗、既存ID優先のマージ、繰り返し復元と再開待ちの予約拒否を検証します。

Android試験APKには、隔離した2保存領域での設定のみ／履歴付き復元、既存Storeインスタンスの再利用、同じファイルの2回復元、保存段階の障害注入、本文の衝突時の既存優先、プレビューキャンセルの試験を追加します。コンパイル成功は端末での実行成功ではありません。

開発環境にはAndroid端末がなく、Google Driveプロバイダー、物理的な別端末のKeystore、実ファイル往復、Androidの障害注入、通知の到着とタップは未実行です。実容量不足や電源断の試験も未実行です。翻訳の自然さもレビュー対象です。ローカルの必須Gradleコマンドは通信制限で配布ZIPを取得できず、GitHub Actionsで実行します。
